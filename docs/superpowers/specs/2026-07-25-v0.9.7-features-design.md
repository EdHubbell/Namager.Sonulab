## Item 1 — Amp/IR list freshness

### Problem

Two independent staleness leaks, both confirmed in source.

**1a. Deleted amps and IRs stay in the parameter-editor dropdowns.**
`ParameterEditorViewModel.LoadCoreAsync` reads the amp/IR name lists (`SonuClient.ReadListAsync`)
once per *preset load*, caching them in the `refOptions` dictionary for that load only.
`LoadForAsync` early-returns when the requested preset is already loaded
(`presetName == _loadedName`). So: delete an amp on the Amps tab, return to Presets with the same
preset still selected → nothing reloads → the deleted amp is still offered in the picker.

**1b. Changing a preset's amp/IR in the editor does not update the preset→amp/IR usage map.**
`ParameterEditorViewModel.SaveAsync` has no reference to `IPresetUsageService` and never notifies
it. `PresetListViewModel` maintains the map on every mutation it performs (`Invalidate()`, or the
targeted `NotifyPresetMoved`/`Renamed`/`Deleted`), but an editor save is invisible to the map. The
Amps and IRs tabs therefore keep reporting the *old* amp as "used by preset NN", and the delete
guard keeps blocking its deletion — which is exactly the workflow (replacing amps that did not come
from Tone3000) that motivated this item.

### Approach: targeted, not blunt

Both fixes are targeted rather than "invalidate everything on any change". The map already has a
targeted-maintenance pattern (`WithMovedSlot`/`WithRenamedPreset`/`WithoutSlot` applied via
`PresetUsageService.Apply`, deliberately leaving `IsComplete` untouched); this extends it rather
than reaching for the 30-preset rescan.

### 1a design — `CatalogVersion`

New `Namager.App.Services.CatalogVersion`: a monotonically increasing `int Version`, a `Bump()`
method, and an `event Action? Changed`. One instance per connection, created in
`MainWindowViewModel`'s `Connected` handler alongside `PresetUsageService`, and passed to
`AmpListViewModel`, `IrListViewModel`, and `ParameterEditorViewModel`.

- The amp and IR list VMs call `Bump()` after any **verified** mutation that changes the name set or
  its order: delete, upload, rename, reorder. (Reorder does not change membership, but the device's
  `read root\amp` list is slot-ordered, so the picker order changes with it. Bumping costs two
  cheap `read` calls on the next Presets visit.) A *failed* mutation does not bump — same discipline
  as the usage-map notifies.
- `ParameterEditorViewModel` records the `CatalogVersion.Version` it last populated pickers with. A
  new `RefreshRefOptionsAsync()`: if the recorded version differs from the current one, re-issue the
  `ReadListAsync` calls for each distinct `ref` target and replace the options on the affected
  fields **in place** — no `browse`, no preset re-select, so unsaved edits survive.
- `ParameterFieldViewModel.Options` becomes settable and observable so the ComboBox picks up the new
  list.
- Trigger: `MainWindow.OnNavSelectionChanged` already calls `vm.EnsureTabLoaded(index)`. Add an
  editor refresh for nav index 0 (Presets). No timers, no polling.

**Deleted-value safety valve.** If a field's current value is absent from the refreshed list (the
referenced amp was deleted out from under the preset), the current value is unioned into the options
so the ComboBox renders the preset's real on-device setting instead of blanking. Blanking would look
like a UI-initiated change and could be saved back as an empty amp reference.

**Failure handling.** A failed `ReadListAsync` leaves the existing options untouched and leaves the
recorded version unchanged, so the next Presets visit retries. Refresh never throws into the UI and
never blocks the tab switch.

### 1b design — `WithUpdatedPreset` + notify on save

`ParameterEditorViewModel` gains an `IPresetUsageService`, a `DeviceRepository`, and the **slot
index** of the loaded preset. Today it only knows the preset *name*.

- New `public sealed record PresetTarget(int Index, string Name)`. `MainWindowViewModel`'s
  selection wiring changes from `editor.LoadForCommand.Execute(sel.Name)` to
  `editor.LoadForCommand.Execute(new PresetTarget(sel.Index, sel.Name))`. `LoadForAsync` keeps its
  existing "already loaded → no-op" dedup, now keyed on the name as before.
- New `IPresetUsageService.NotifyPresetContentChangedAsync(int index, string name, CancellationToken)`:
  reads the head of **that slot only** (`DeviceRepository.ReadPresetHeadAsync(index, background: false)`
  — windowed, ≤32 chunks, normally stopping early once the three ref lines are complete), then
  applies `PresetUsageMap.WithUpdatedPreset(index, name, doc)` through the existing `Apply` path so
  `MapUpdated` fires and the Amps/IRs tabs re-highlight.
- New pure method `PresetUsageMap.WithUpdatedPreset(int index, string name, PresetDocument doc)`:
  drop every ref at `index`, then add the refs parsed from `doc` using the same path-matching rules
  as `Build` (`AmpNodePath`, `IsIrRefPath`). Fully unit-testable, no device I/O.
- `ParameterEditorViewModel.SaveAsync` calls it after a successful save.

**Failure handling.** If the head read or the patch fails, fall back to `_usage.Invalidate()` (full
rescan) and log. A map-refresh failure must never fail or appear to fail the save — the preset *was*
written. `NullPresetUsageService` gets a no-op implementation so existing VM tests keep working.

**Cost.** One head read on the foreground lane per editor save, awaited inside the save's status
operation. Compare to `Invalidate()`, which costs a full 30-preset background rescan.

### Resulting workflow

Change a preset's amp in the editor → Save → the previous amp immediately reads as unused on the
Amps tab and the delete guard releases it → delete it → return to Presets → it is gone from the
dropdown.

### Tests

- `PresetUsageMap.WithUpdatedPreset`: ref moved from amp A to amp B; ref removed entirely (empty
  value); a preset gaining a second IR; a preset index with no prior refs; other slots untouched.
- `ParameterEditorViewModel`: a successful save calls `NotifyPresetContentChangedAsync` with the
  loaded slot index; a failed save does not; a failing notify does not surface as a save error.
- `AmpListViewModel` / `IrListViewModel`: delete/upload/rename/reorder bump the version on success;
  a failed mutation does not.
- `ParameterEditorViewModel.RefreshRefOptionsAsync`: no-ops when the version is unchanged; replaces
  options when bumped; unions in a current value missing from the new list; leaves options intact
  when the read throws.

## Item 2 — Per-preset download and upload

### Editor toolbar (`ParameterEditorView`)

- **Remove the `Load` button**, and with it `LoadCommand`/`LoadAsync` on the VM — dead code, since
  `LoadForAsync` is the path every real load takes. `LoadCoreAsync` stays.
- **`Save` becomes an icon button** (`Icon.Save`, the existing floppy geometry) with tooltip
  "Save preset to pedal". The unsaved-changes dot stays.
- **New download button** (new `Icon.Download` down-arrow geometry) with tooltip
  "Download preset to PC": `DeviceRepository.ReadPresetAsync(index)` → save-file picker defaulting
  to `NN - Name.pst` (matching `BackupService`'s naming so downloads and backups interoperate) →
  `File.WriteAllBytesAsync(path, doc.ToBytes())`.
- If the editor `IsDirty`, confirm first: the downloaded file contains what is on the pedal, not the
  unsaved edits. The user may proceed or cancel.

### Preset-list toolbar (`PresetListView`)

**New upload button** (new `Icon.Upload` up-arrow geometry), tooltip "Upload preset from PC":

1. Open-file picker filtered to `*.pst`.
2. `PresetDocument.Parse(bytes)`. A malformed file fails here, **before any device write**, and
   surfaces as `ErrorMessage`.
3. Derive the name from the filename stem, stripping a leading `NN - ` if present (the inverse of
   `BackupService`'s convention), then cap at the device's 31-char limit.
4. **Clash resolution.** If a preset with that name already exists, find the lowest free
   `"{base} #{n}"` starting at `n = 2`, truncating `base` so the whole name stays within 31 chars.
   Warn the user in the status bar, naming both the requested and the actual name. Uniqueness is not
   cosmetic here: `write root\app\preset` + `"save":"save"` targets the slot **by name**, so a
   duplicate name would make later save-from-live operations ambiguous.
5. **Target slot.** First empty slot. If the pedal is full, open a dialog listing all 30 slots and
   ask which one to overwrite; cancel aborts with no write.
6. Write with `DeviceRepository.WritePresetToSlotAsync(slot, name, doc, verify: true)` — the
   byte-exact dwrite path (~10 s), which already read-back-verifies. Status shows an indeterminate
   operation naming the preset and the expected duration.
7. On success: reload the list and patch the usage map targeted via
   `NotifyPresetContentChangedAsync`. `CatalogVersion` is **not** bumped — preset changes do not
   affect amp/IR pickers.

### Structure

File pickers and dialogs live in view code-behind, following the existing
`AmpListView.axaml.cs` pattern (`TopLevel.GetTopLevel(this).StorageProvider`). View models take
plain file paths and expose commands, so they stay unit-testable with no UI dependency and no new
dialog abstraction.

### Tests

- Name derivation: `"07 - Clean Verb.pst"` → `"Clean Verb"`; a stem with no `NN - ` prefix passes
  through; an over-long stem is truncated to 31.
- Clash resolution: first free `#n` is chosen; base truncation keeps the result ≤31; no clash leaves
  the name untouched.
- Upload: a malformed `.pst` produces an error and issues no device write; a successful upload
  targets the first empty slot and patches the map; a full pedal routes to the overwrite prompt;
  cancelling the prompt writes nothing.
- Download: writes `doc.ToBytes()` verbatim; dirty-editor confirmation is requested.

## Item 3 — Application menu bar

A `Menu` docked at the top of `MainWindow`, above the existing connection bar.

### File

- **Backup Presets…** — `BackupService.SnapshotAllAsync` into
  `Documents\NAMager Backups\yyyy-MM-dd HHmm\`. A fixed timestamped destination, no folder prompt:
  one click to back up, and every run is preserved. Progress runs through `StatusService`. On
  completion a small dialog reports the count and the full path with an **Open Folder** button — the
  status bar is a single elided line and the path is too long to read there.
  *Note:* `BackupService` currently defaults to the relative `docs/backups`, which resolves against
  the install directory for a shipped build. The menu passes an absolute path; the relative default
  stays only for the dev harness.
- **Restore Presets…** — folder picker → enumerate `*.pst` → parse `NN - Name.pst` for the target
  slot → confirmation dialog listing exactly which slots will be overwritten, stating plainly that
  slots without a matching file are left untouched → sequential `BackupService.RestoreSlotAsync`
  with N/M progress, cancellable between slots. Files whose names do not match the `NN - ` pattern
  are skipped and reported in the summary rather than guessed at.
  At roughly 10 s per slot, a 12-preset restore takes about two minutes — hence the progress and the
  cancel.
- **Exit** — closes the window.

Backup and Restore are disabled while disconnected; Restore is additionally gated on
`WritesAllowed`.

### Settings

- **Theme ▸ Light / Dark / System** — radio-style `MenuItem`s, applied immediately by setting
  `Application.Current.RequestedThemeVariant`. System is the default and matches today's behavior
  (`App.axaml` ships `RequestedThemeVariant="Default"`), so existing users see no change unless they
  choose. The theme is already fully token-driven with both variants defined in
  `Styles/SonulabTheme.axaml` and in the Fluent accent-ramp override, so no new color work is needed.
- Persisted to `%APPDATA%\Namager\settings.json` via a new `AppSettings` record and
  `AppSettingsStore` in `Namager.App.Services` — the same directory Tone3000 config already uses.
  Loaded in `App.axaml.cs`'s `OnFrameworkInitializationCompleted` *before* the window is shown, so a
  dark-theme user never sees a light flash.
- A corrupt or unreadable settings file falls back to defaults rather than failing startup.

### Help

- **About** — a small `Window` following the `FeedbackDialog` pattern: the app name,
  `AppInfo.Version`, and "Created by ed@gsdware.com".

### Tests

- `AppSettingsStore`: round-trips a theme choice; returns defaults for a missing file; returns
  defaults for a corrupt file without throwing.
- Restore planning (pure): maps a folder listing to slot/name pairs; skips non-conforming filenames
  and reports them; produces the confirmation summary.

## Out of scope

- Backing up or restoring **amps and IRs**. Both menu items are named "…Presets" precisely so the
  boundary is visible in the UI. Amp/IR backup would need new core work (30 slots × 12 KB of chunk
  reads for amps alone) and is a separate feature.
- A "last backup folder" setting — the destination is fixed and timestamped, so there is nothing to
  remember.
- Reconnect-in-place, WiFi re-enablement, or any transport change.
